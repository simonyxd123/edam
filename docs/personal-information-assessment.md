## 一、评估范围

### 1.1 系统边界

- **EDAM 系统**：视频/文档防泄密系统
- **相关业务**：员工身份认证、资源访问、外发审批、审计日志
- **数据范围**：员工个人信息（姓名、工号、邮箱、电话、操作记录）
- **部署环境**：内网 + 互联网（VPN 强制）

### 1.2 评估数据项

| 数据项 | 敏感性 | 收集 | 存储 | 使用 | 共享 |
| --- | --- | --- | --- | --- | --- |
| 姓名 | 中 | ✅ | ✅ | ✅ | ❌ |
| 工号 | 中 | ✅ | ✅ | ✅ | ❌ |
| 邮箱 | 中 | ✅ | ✅ | ✅ | ⚠️（外发审批时）|
| 手机号 | 高 | ✅ | ✅ | ✅ | ❌ |
| 部门 | 低 | ✅ | ✅ | ✅ | ❌ |
| 操作日志 | 高 | ✅ | ✅ | ✅ | ❌ |
| 视频观看记录 | 中 | ✅ | ✅ | ✅ | ❌ |

### 1.3 数据流向

```
员工输入 → HTTPS (TLS 1.2+) → API 网关
                                ↓
                后端 → 写入 MySQL（加密 PII 字段）
                                ↓
                ELK → 审计日志（180 天）
                                ↓
                Vault → 密钥管理（90 天轮转）
```

## 三、安全性评估

### 3.1 技术措施

| 维度 | 措施 | 满足情况 |
| --- | --- | --- |
| 加密传输 | TLS 1.2+ | ✅ |
| 加密存储 | AES-256-GCM（字段级）| ✅ |
| 密钥管理 | Vault Transit + 90 天轮转 | ✅ |
| 访问控制 | RBAC + 资源 ACL | ✅ |
| 审计日志 | ELK + 180 天 + WORM | ✅（v3.3 W-1 G-3）|
| 漏洞管理 | Trivy + Snyk + ZAP（CI 集成）| ✅（v3.3 W-1 G-8）|
| 密码策略 | 16 位 + 90 天 + 历史 5 条 | ✅（v3.3 W-1 G-5）|
| 集中监控 | SOC + 告警 | 🔲（v3.3 W-1 G-2）|

### 3.2 组织措施

| 维度 | 措施 |
| --- | --- |
| 人员管理 | 背景调查 + 保密协议 + 离职交接 |
| 权限分离 | 三权分立（系统管理员 / 安全管理员 / 审计管理员）|
| 培训 | 入职信息安全培训 + 年度复训 |
| 应急响应 | 故障 SOP + 演练（v3.3 W-1 G-7）|
| 第三方管理 | 外包人员保密协议 + 权限限制 |

### 3.3 残余风险

| 风险 | 可能性 | 影响 | 缓解 |
| --- | --- | --- | --- |
| 内部员工主动泄露 | 低 | 高 | HR + 法务 + 频域水印 |
| 第三方供应商泄露 | 低 | 高 | 保密协议 + 供应商评估 |
| 外部黑客攻击 | 中 | 高 | WAF + EDR + 渗透测试 |
| 数据库泄露 | 低 | 极高 | TDE + WORM + 异地备份 |

## 四、PIA 结论

### 4.1 综合评价

| 维度 | 评分（5） |
| --- | --- |
| 合法性 | 5 |
| 必要性 | 5 |
| 安全性 | 4 |
| 透明度 | 4 |
| 主体权利保障 | 4 |

**总分**：4.4 / 5（优秀）

### 4.2 主要风险

1. **员工监控透明度**：当前监控系统未主动告知员工（建议年度告知）
2. **个人信息影响评估**：本评估是首次，未来需年度更新
3. **跨境数据传输**：无（系统不涉及跨境）

### 4.3 改进建议

1. **告知书年度更新**：每年度更新《信息安全与监控告知书》
2. **PIA 年度评估**：每年由法务 + 安全 + DPO（未来）联合评估
3. **删除权落实**：员工离职 30 天后，硬删除 PII 数据（合规要求）
4. **数据最小化**：定期审查 sys_user 表字段，必需字段保留

### 4.4 是否可以继续运营

✅ **可以继续运营**，条件：

- 完成 v3.3 W-1 等保 P0 整改（9 项）
- 完成 v3.3 W-3 商密认证
- 年度 PIA 复评
- 持续运营安全监控

## 五、PIA 维护机制

### 5.1 触发复评的事件

- 系统功能重大变更（如新增模块）
- 法规变化（如 PIPL 修订）
- 数据泄露事件
- 每年 1 次例行复评

### 5.2 复评流程

1. 触发事件发生
2. 启动 PIA 复评（法务 + 安全 + 业务）
3. 评估变更影响
4. 输出复评报告
5. 调整安全措施
7.  管理层批准

### 5.3 报告归档

- 本文档：`docs/personal-information-assessment.md`
- 历史版本：`docs/personal-information-assessment-YYYYMMDD.md`
- 复评记录：Jira / 飞书任务
