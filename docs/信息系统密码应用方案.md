## 第 1 章 系统概述

### 1.1 系统简介

EDAM（Enterprise Digital Asset Management）是企业级数字资产防泄密系统，覆盖视频与文档两类核心资产，提供：

- 上传与预处理（HLS 切片 + DCT 频域水印 + pHash 指纹）
- 加密存储（MinIO + 服务端加密）
- 访问授权（RBAC + 资源级 ACL）
- 外发审批（多级审批 + 阅后即焚）
- 审计溯源（操作日志 + 频域水印提取）
- 多端支持（iOS + Android 原生 SDK）

### 1.2 信息资产

| 资产类别 | 密级 | 数量级 |
| --- | --- | --- |
| 视频文件 | L1-L4 | 10 万 |
| 文档文件 | L1-L4 | 50 万 |
| 用户身份信息 | L3 | 万级 |
| 操作日志 | L3 | 千万级 |
| 系统密钥 | L4 | 数十 |
| 审计日志 | L3 | 千万级 |

### 1.3 部署环境

- **生产**：K8s 集群（5 节点）+ 阿里云 VPC
- **预生产**：K8s 集群（3 节点）
- **开发**：Docker Compose（单机）
- **数据库**：MySQL 8.0 主从 + Redis Cluster + MinIO + Vault
- **CDN**：阿里云 CDN（私有）
- **终端**：员工 Windows / macOS / Linux / iOS / Android

### 4.3 计算与环境层

| 项 | 措施 |

| 心跳上报 | 每 5 分钟（防止离线攻击）|

### 4.4 应用与数据层

#### 4.4.1 用户身份认证

| 流程 | 算法 |
| --- | --- |
| 登录密码哈希 | bcrypt + SM3 摘要 |
| 密码传输 | 国密 TLS |
| 密码存储 | bcrypt(cost=12) |
| MFA | TOTP（HMAC-SM3）|
| 密码轮转 | 90 天（管理员/敏感岗位 60 天）|
| 密码历史 | 5 次不能重复 |

#### 4.4.2 JWT Token 签名

```yaml
默认: HS256 (HMAC-SHA256)
国密模式: GS256 (SM3-HMAC)
配置切换: edam.jwt.algorithm=GS256
密钥来源: Vault Transit (密钥 ID: edam-jwt-key)
轮转周期: 180 天
灰度期: 7 天双密钥并行
```

#### 4.4.3 HLS 视频加密

```yaml
L1/L2 密级: AES-128-CBC (国际算法)
L3/L4 密级: SM4-CBC (国密算法, 强制)
密钥来源: Vault Transit (密钥 ID: edam-hls-key)
IV 长度: 16 字节 (AES) / 16 字节 (SM4)
轮转周期: 90 天
HLS 标签: EXT-X-KEY METHOD=SAMPLE-AES (AES) / 自定义 (SM4)
```

#### 4.4.4 文档加密存储

| 存储位置 | 算法 |
| --- | --- |
| MinIO 服务端加密 | AES-256-SSE-S3 + SM4-GCM (应用层) |
| 字段级加密（real_name/email/phone） | SM4-GCM |
| 频域水印嵌入 | DCT + SM3 摘要 |

#### 4.4.5 PII 字段加密

```yaml
算法: SM4-GCM (国密) + AES-256-GCM (国际) 双轨
密级: L3+ 强制国密
密钥: Vault Transit (edam-pii-key)
轮转: 90 天 KEK + 365 天 DEK
```

### 4.5 密钥管理层

#### 4.5.1 密钥生命周期（6 阶段）

| 阶段 | 措施 |
| --- | --- |
| 生成 | 商用 HSM（KHS））生成，熵源 `/dev/urandom` + 硬件 TRNG |
| 存储 | Vault Transit（生产 HSM） |
| 分发 | Vault Token（短期 ≤ 24h） |
| 使用 | 国密 TLS + 应用层封装 |
| 更新（轮转）| 90 天（HMAC）/ 180 天（JWT）/ 365 天（DEK）|
| 销毁 | 标记 `status=retired` → 重新加密依赖数据 → 删除 |

#### 4.5.2 密钥清单（11 种）

| 密钥 ID | 类型 | 算法 | 用途 | 轮转 |
| --- | --- | --- | --- | --- |
| edam-hls-key | KEK | SM4 | HLS 视频 | 90d |
| edam-doc-key | KEK | SM4 | 文档存储 | 90d |
| edam-pii-key | KEK | SM4 | PII 字段 | 90d |
| edam-data-key | DEK | SM4 | 数据加密 | 365d |
| edam-jwt-key | 签名 | SM3-HMAC | JWT 签名 | 180d |
| edam-webhook-secret | HMAC | SM3-HMAC | Webhook 签名 | - |
| edam-driver-master | KEK | SM4 | 驱动主密钥（备查）| 90d |
| edam-sm4-hls | KEK | SM4 | 国密 HLS | 90d |
| edam-sm3-jwt | HMAC | SM3 | JWT 国密摘要 | 180d |
| edam-mfa-totp | HMAC | SM3-HMAC | TOTP | 不 |
| edam-vault-unseal | 随机 | 256 bit | Vault 解封 | 7 节点 |

## 第 5 章 密钥管理

### 5.1 密钥生成

| 算法 | 长度 | 工具 | 熵源 |
| --- | --- | --- | --- |
| SM4 | 128 bit | 商用 HSM | TRNG + `/dev/urandom` |
| SM2 | 256 bit | 商用 HSM | TRNG |
| SM3 | 256 bit | 商用 HSM | TRNG |

### 5.2 密钥存储

| 存储位置 | 加密方式 | 访问控制 |
| --- | --- | --- |
| HSM（生产） | 不解密，明文仅在 HSM 内部 | 双因素认证 |
| Vault（开发） | 主密钥加密 + unseal key 分片 | AppRole + 短期 Token |
| 数据库 | 应用层加密（SM4-GCM） | RBAC + 字段级 ACL |

### 5.3 密钥分发

| 分发方式 | 工具 | 加密 |
| --- | --- | --- |
| 应用层 | Vault Token (TTL ≤ 24h) | TLS |
| 终端 | MDM 推送 | 国密 TLS |
| 微服务 | Service Token | TLS |

### 5.4 密钥轮转

| 周期 | 密钥类型 |
 | --- | --- |
| 90 天 | HLS / DOC / PII KEK |
| 180 天 | JWT 签名密钥 |
| 365 天 | DEK |
| 即时（泄露时）| 全部密钥 |

**轮转流程**：
1. 生成新密钥 v_new
2. 双密钥并行（14 天灰度）
3. 灰度结束：废弃 v_old
4. 重新加密依赖数据

### 5.5 密钥销毁

| 销毁场景 | 措施 |
| --- | --- |
| 生命周期结束 | `key_rotation_log.status = retired` |
| 泄露事件 | 立即销毁 + 强制轮转 |
| 业务下线 | 数据迁移后销毁 |

### 5.6 密钥审计

| 审计项 | 频率 |
| --- | --- |
| 密钥使用记录 | 每次（实时）|
| 密钥轮转日志 | 每次轮转 |
| 异常访问 | 实时告警 |
| 密钥备份校验 | 每周 |
