## ADR 规范

每篇 ADR 包含：
- **状态**：提议 / 已接受 / 已废弃
- **日期**：决策日期
- **修订历史**：如有修订，列出变更点
- **上下文**：为什么需要做决策
- **评估**：可选方案的对比
- **决策**：最终选择 + 理由
- **风险与缓解**：识别风险 + 缓解措施
- **后果**：正向/负向/缓解

## 命名规范

```
NNNN-<kebab-case-title>.md
```

- `NNNN`：4 位顺序编号（0001, 0002, ...）
- `<title>`：英文短横线连接

## 修订流程

1. **不修改历史 ADR**：已接受的决策记录在原文件中
2. **新决策创建新 ADR**：如 ADR-0001 v2.0 创建为 ADR-0008
3. **修订历史**：在原 ADR 顶部加"修订"行，说明变更原因
4. **状态变更**：如决策被推翻，将状态改为"已废弃"并注明替代方案

## 与方案书的关系

- 方案书（v3.0）：描述**做什么**
- ADR：**为什么这么做**、**评估了哪些替代方案**、**权衡了哪些因素**

未来维护：
- 任何架构级变更需先写 ADR 评审
- ADR 通过后才更新方案书
- 每季度回顾现有 ADR 是否仍然适用
