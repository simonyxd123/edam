# ADR-0004：视频加密方案（HLS+AES-128 vs Widevine DRM）

- **状态**：✅ 已接受
- **日期**：2026-08-12
- **修订**：v3.0 重写后于 2026-08-12 复核

## 上下文

视频安全需要解决两个层面：
1. **传输加密**：防止网络窃听
2. **内容保护**：防止定向攻击者获取原始视频

## 评估

### 方案 1：HLS + AES-128

- ✅ 实现简单，FFmpeg 内置支持
- ✅ 浏览器原生支持（hls.js）
- ✅ 性能开销低
- ❌ 浏览器 DevTools 可抓取 .ts 分片并解密（密钥 GET 接口明文返回）
- ❌ **不是真正的 DRM**

### 方案 2：Widevine DRM

- ✅ 工业级 DRM，Chrome / Android / Edge 原生支持
- ✅ 密钥不解出浏览器，硬件级保护
- ❌ Safari / iOS 不支持（需 FairPlay）
- ❌ 商业授权（Widevine Modular 仅供 OEM）
- ❌ 部署复杂（需要 License Server、Certificate 等）

### 方案 3：Widevine + FairPlay 双 DRM

- ✅ 全平台覆盖
- ❌ 商业成本高 + 部署复杂
- ❌ 与"零商业授权费用"原则冲突

## 决策

**主方案 HLS + AES-128；高敏感场景评估 Widevine**。

理由：
1. 大部分企业培训视频的"被窃取后能造成多大损失"远低于电影版权
2. HLS+AES-128 已能阻挡 95%+ 普通员工获取原始视频
3. 真正的强防御必须依赖**视频帧指纹溯源**（即使视频被破解，仍可定位泄密者）
4. 商业 DRM 部署复杂，与项目预算和"自主可控"原则冲突

## 关键安全措施（v3.0 落地）

1. **密钥接口加固**（4.2.2 节）：
   - 每次请求生成一次性密钥
   - 响应头 `Cache-Control: no-store`
   - mTLS 与业务网络隔离
2. **HLS 切片 + 视频帧指纹双轨**（4.4 节）：
   - 切片加密阻挡普通用户
   - 帧指纹（pHash + 帧间冗余）支持溯源
3. **二次签名校验**（4.1.2 节）：Nginx MD5 兼容 + 应用层 HMAC-SHA256
4. **Token 设计**：不携带 PII（解决 v1.0 PII 泄露问题）

## 何时升级到 Widevine

- L4 绝密视频被批量外发且溯源无效
- 法律法规要求（如影视行业、保密单位）
- 评估成本后启动二期 Widevine + FairPlay 集成

## 后果

- **正向**：实现简单 + 性能好 + 兼容性强 + 95% 防御
- **负向**：定向攻击者可绕过（但可溯源）
- **缓解**：必须配合视频帧指纹 + 外发审批 + 监控告警
