# ADR-0001：自研 vs 采购 DLP（数据防泄密）方案

- **状态**：✅ 已接受
- **日期**：2026-08-12
- **决策人**：安全团队 / 架构组

## 上下文

公司计划建设全格式数字资产防泄密系统，目标是保护内部培训视频、核心设计文档、机密报告等数字资产。

**可选方案**：
1. 采购商业 DLP 产品（IP-guard、深信服、天喻、Symantec DLP、Microsoft Purview）
2. 采购 + 部分自研（混合模式）
3. 全部自研（基于开源技术栈）

## 评估

### 方案 1：采购商业 DLP

- ✅ 成熟稳定，落地快
- ✅ 厂商提供持续维护
- ✅ 跨平台支持好
- ❌ 商业授权费用高（百万级/年）
- ❌ 定制化能力差，难以满足"千人千面"水印等深度需求
- ❌ 核心算法不透明，无法审计安全性
- ❌ 与公司现有技术栈（Java + Vue + MySQL）整合成本高

### 方案 2：混合模式

- ✅ 商用产品覆盖通用场景（终端管控、邮件外发拦截）
- ❌ 仍存在授权费用
- ❌ 视频防泄密等深度需求仍需自研

### 方案 3：全部自研

- ✅ 零商业授权费用
- ✅ 完全可控、可定制、可审计
- ✅ 与现有技术栈深度整合
- ❌ 驱动层开发工作量大（10-14 人月）
- ❌ 跨平台兼容性需自验证
- ❌ 安全责任完全自担

## 决策

**采用方案 3：基于开源技术栈全部自研**。

理由：
1. 公司已有较强的 Java/Python 开发能力，驱动层开发虽有风险但可控
2. "零商业授权费用"是核心卖点
3. 核心算法（频域水印、帧指纹）需要自研，与商业 DLP 集成的成本不亚于自研
4. 商业 DLP 产品的"通用性"与公司"千人千面"需求矛盾

## 风险与缓解

| 风险 | 缓解 |
| --- | --- |
| 驱动层开发延期 | 优先 Windows 平台（覆盖率最高），macOS/Linux 二期；预留 Buffer |
| 跨平台兼容性 | 阶段 5 联调测试，3-4 人月 |
| 安全漏洞 | CVE 监控 + 季度渗透测试 + bug bounty（v3.2 评估） |
| 维护成本 | 长期 0.5 SRE + 季度迭代 |

## 后果

- **正向**：零授权费用 + 深度定制 + 完全可控
- **负向**：开发周期 8-12 个月，初期安全责任完全自担
- **回顾**：v3.0 终稿时回顾（已通过评审）
