## 一、密级定义（4 级）

| 级别 | 名称 | 访问要求 | 适用场景 |
| --- | --- | --- | --- |
| **L1** | 公开 | 所有员工 + 外部 | 公司简介、产品手册、公开资料 |
| **L2** | 内部 | 全员 | 项目计划、周报、会议纪要、Roadmap |
| **L3** | 机密 | 部门/项目组 | 合同、审计、法务、人事、薪酬 |
| **L4** | 绝密 | 少数核心人员 | 军工、核武器、并购、战略 |

## 二、自动识别维度

按优先级（数字越小优先级越高）：

| 优先级 | 维度 | 规则 | 目标密级 |
| --- | --- | --- | --- |
| 10 | 文件名关键词 | 绝密/最高机密/核武器/军工/涉密 | L4 |
| 20 | 文件名关键词 | 合同/合规/审计/法务/人事/薪酬 | L3 |
| 21 | 文件名关键词 | 机密/核心/战略/股权/并购/未公开/内幕 | L3 |
| 30 | 文件名关键词 | 内部/项目/Roadmap/规划/周报/月报 | L2 |
| 40 | 部门 | HR/法务/审计 | L3 |
| 41 | 部门 | 财务 | L2 |
| 50 | 文件大小 | > 5GB | L4 |
| 51 | 文件大小 | > 1GB | L3 |
| 52 | 文件大小 | > 100MB | L2 |

### 2.1 综合识别算法

```
1. 用户手动选择（最高优先）
2. 文件名关键词（L4/L3 直接采用）
3. 文件大小（L3+ 直接采用）
4. 部门
5. 取以上最高的密级
```

## 三、强制打标（上传时）

### 3.1 上传流程

```
用户上传文件
   ↓
强制打标中间件（ClassificationEnforcement）
   ↓
1. 文件名关键词识别
2. 文件大小识别
3. 上传者部门识别
4. 用户手动选择（如有）
5. 取最高密级
   ↓
写入 video_resource.classification_lv / doc_resource.classification_lv
   ↓
审计：data_classification_audit（auto 变更）
```

### 3.2 数据库表

- `video_resource.classification_lv`（已有）
- `doc_resource.classification_lv`（已有）
- `sys_user.default_classification`（新增 V20260828）

### 3.3 强制 vs 自由选择

| 策略 | 行为 |
| --- | --- |
| **强制** | 系统自动打标 + 用户不可更改 |
| **自由选择（默认）** | 系统推荐 + 用户可调整（只能调高不能调低）|
| **禁止分类** | 用户无法选择密级 |

**默认策略**：自由选择（只能上调）+ 审计追踪

## 四、密级变更审计

### 4.1 审计规则

| 场景 | 是否记录 |
| --- | --- |
| 上传时自动分类 | ✅（change_method=auto）|
| 用户手动调整（上调）| ✅（change_method=manual）|
| 用户手动调整（下调）| ⚠️ 需要二次确认（管理员审批）|
| 管理员强制调整 | ✅（change_method=manual + 原因）|
| 批量重新分类 | ✅（change_method=rule）|

### 4.2 审计字段

| 字段 | 含义 |
| --- | --- |
| resource_type | video / document |
| resource_id | 资源 ID |
| old_classification | 旧密级 |
| new_classification | 新密级 |
| change_reason | 变更原因 |
| changed_by | 变更人 |
| change_method | auto / manual / rule |
| rule_id | 触发的规则 ID（自动时） |
| changed_at | 变更时间 |

### 4.3 保留期

**730 天**（2 年诉讼时效）

## 五、人工变更流程

### 5.1 用户调整（上调）

```
1. 用户提交调整请求（理由）
2. 系统校验：新密级 >= 旧密级
3. 写入新密级 + 审计
4. 完成（无需审批）
```

### 5.2 用户调整（下调）

```
1. 用户提交调整请求（理由）
2. 系统校验：新密级 < 旧密级 → 触发审批
3. 通知部门管理员 + 安全审计员
4. 审批通过 → 写入 + 审计
5. 审批拒绝 → 保持原密级
```

### 5.3 管理员强制调整

```
1. 管理员选择资源 + 新密级 + 理由
2. 直接写入 + 审计（无需审批）
3. 通知资源所有者
```
