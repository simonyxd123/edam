## 二、应急事件分类

### 2.1 数据泄露事件

**触发场景**：
- 内部员工主动或被动外发敏感数据
- 外部黑客入侵导致数据外泄
- 第三方供应商泄露
- 物理介质丢失（笔记本、U盘）

**响应流程**：
```
T+0   收到泄露报告（来源：客户/员工/监控）
T+5   应急小组成立（技术 + 安全 + 法务）
T+15  确认泄露范围（影响用户数 + 数据类型）
T+30  启动技术止损（吊销密钥 / 切断通道）
T+60  启动溯源（频域水印提取 / 日志分析）
T+2h  内部通报（高管 + 相关部门）
T+24h 法务评估（个保法 / 监管要求）
T+72h 外部通报（如需，按 GB/T 35273）
T+7d  整改完成 + 复盘报告
```

**技术响应清单**：
- [ ] 吊销涉事用户所有 session + 密钥
- [ ] 冻结涉事账户
- [ ] 启动溯源：
  - 频域水印 / pHash 指纹提取
  - operation_log 检索
  - nginx access_log  检索
- [ ] 评估下游影响（已下载用户的访问日志）
- [ ] 加固防御（同类型攻击的二次防范）

### 2.2 系统故障事件

**触发场景**：
- 服务完全不可用（数据库挂、网络断、K8s 节点全挂）
- 部分功能不可用（特定 API 返回 5xx）
- 性能严重下降（P99 > 10s）

**响应流程**：
```
T+0   监控告警触发（Prometheus Alertmanager）
T+5   值班工程师确认 + 启动应急
T+15  故障定级（P0/P1/P2）
T+30  启动应急预案（Runbook）
T+1h  故障缓解（恢复服务 / 启用降级）
T+4h  故障根因定位
T+24h 故障修复
T+7d  复盘 + 改进
```

**降级方案**（按优先级）：
1. 只读模式（disable write APIs）
2. 切换镜像（DR 站点）
3. 限流保护（API Gateway）
4. 关闭非核心功能（通知、审计、统计）

### 2.3 安全攻击事件

**触发场景**：
- DDoS 攻击
- SQL 注入 / XSS
- 越权访问尝试
- 暴力破解
- 内部异常行为

**响应流程**：
```
T+0   WAF / IDS 告警 / SOC 检测
T+5   安全分析师介入
T+15  临时封禁（IP / 用户 / 攻击向量）
T+30  评估影响范围
T+1h  加固防御（紧急补丁）
T+24h 溯源 + 报告（监管 / 法务）
```

## 三、应急预案 SOP

### 3.1 Vault 故障应急

**触发**：Vault 集群脑裂 / 网络分区 / HSM 失联

**响应**：
1. 业务进入「只读降级」模式
2. 检查 Vault Raft 状态：`vault operator raft list-peers`
3. 重启失联节点
4. 验证 unseal 状态
5. 恢复后逐服务解除降级

**RTO**：30 分钟 | **RPO**：5 分钟

### 3.2 数据库故障应急

**触发**：MySQL 主库宕机 / 数据损坏 / binlog 中断

**响应**：
1. 触发主从切换（MHA / Orchestrator）
2. 应用层切换数据源（VIP / DNS）
3. 验证新主库可写
4. 旧主库修复后加入集群

**RTO**：15 分钟 | **RPO**：5 分钟

### 3.3 MinIO 故障应急

**触发**：MinIO 节点宕机 / 存储损坏

**响应**：
1. MinIO 纠删码自动触发（EC:K=4, M=2）
2. 临时禁用上传接口
3. 启动存储节点重建
4. 数据校验 + 恢复

**RTO**：1 小时 | **RPO**：0（纠删码保护）

### 3.4 K8s 节点故障

**触发**：节点宕机 / 网络分区 / 资源耗尽

**响应**：
1. K8s 自动 reschedule（30s 内）
2. 检查 Pod 状态（`kubectl get pods`）
3. 检查节点状态（`kubectl describe node`）
4. 必要时手动 drain + replace

**RTO**：5 分钟 | **RPO**：0（多副本）

## 六、复盘机制

### 6.1 Blameless 复盘原则

- **不追责个人**：目的是改进系统，而非追究责任
- **聚焦流程**：找流程漏洞，非个人失误
- **5 个 Why**：从表面问题追溯根因
- **产出改进**：每条改进指定责任人 + 时间

### 6.2 复盘输出

- 演练报告（含改进清单）
- Runbook 更新
- 监控告警更新
- 文档更新

### 6.3 跟踪机制

- 改进项录入 Jira / 飞书任务
- 每月复盘会跟进进度
- 90 天后评估改进效果
