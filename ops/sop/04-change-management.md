# 运维 SOP-04：变更管理

> 适用范围：EDAM 系统所有生产环境变更
> 版本：v3.1 / 2026-08-12

## 1. 变更分级

| 等级 | 类型 | 审批 | 窗口 | 沟通 |
| --- | --- | --- | --- | --- |
| **L0 紧急** | P0 故障修复 / 安全补丁 | 值班 SRE | 任何时间 | 立即通报 |
| **L1 重要** | 架构变更 / 数据库 schema | 技术总监 + SRE 负责人 | 周三 02:00-06:00 | T-3 天 |
| **L2 普通** | 功能发布 / 性能优化 | 模块负责人 | 周三 02:00-06:00 | T-1 天 |
| **L3 微型** | 配置变更 / 文案更新 | 团队内部 | 工作时间 | 无 |

## 2. 变更流程

```
申请（Change Request）
  ↓
风险评估（影响范围 / 回滚方案 / 验证步骤）
  ↓
技术评审（代码 Review / 架构 Review）
  ↓
审批（按变更等级）
  ↓
预发布环境验证
  ↓
生产变更执行
  ↓
验证与监控（24 小时）
  ↓
关闭变更 + 归档
```

## 4. 变更执行 Checklist

### 4.1 发布前

- [ ] 变更申请已审批
- [ ] 代码已合并到 main
- [ ] CI 全绿（lint / test / build / security）
- [ ] 镜像已构建并推送到仓库
- [ ] 预发布环境完整测试
- [ ] 数据库迁移脚本已 dry-run
- [ ] 备份已完成
- [ ] 通知已发出
- [ ] 值班人员已就位

### 4.2 发布中

- [ ] 镜像版本记录（Git SHA）
- [ ] Helm 升级命令记录
- [ ] 数据库迁移命令记录（如适用）
- [ ] 关键指标截图（变更前/中/后）
- [ ] 时间戳记录

### 4.3 发布后

- [ ] 健康检查通过（/health/ready）
- [ ] 关键 API 验证（登录/列表/播放）
- [ ] 监控指标正常
- [ ] 错误率无上升
- [ ] 性能无明显下降
- [ ] 24 小时观察无异常
- [ ] 变更关闭通知

## 5. 回滚策略

### 5.1 应用回滚

```bash
# Helm 回滚
helm history edam -n edam           # 查看历史
helm rollback edam 5 -n edam         # 回滚到第 5 个版本

# 镜像回滚
kubectl set image deployment/edam-edam-backend \
    backend=edam/backend:v3.0.0 -n edam
```

### 5.2 数据库回滚

```bash
# 前向修复（推荐）：写新的 V__xxx.sql 修复
# 反向回滚（谨慎）：U__xxx.sql
flyway -url=jdbc:mysql://<host>/edam -user=root -password=xxx \
       -locations=filesystem:dev/db/migration \
       undo
```

### 5.3 配置回滚

```bash
# GitOps 自动回滚
argocd app rollback edam --revision <previous>
```

## 6. 变更窗口

### 6.1 标准变更窗口

- **生产**：周三 02:00-06:00（业务最低峰）
- **预发布**：任何时间
- **开发**：任何时间

### 6.2 紧急变更

P0 故障可任何时间执行，事后 24 小时内补变更申请。

### 6.3 禁止变更窗口

- 重大节假日（春节 / 国庆）
- 公司财报发布日
- 重大活动期间
- 月底财务结算

## 8. 变更记录归档

所有变更必须归档至 `ops/change-log/`：

```
ops/change-log/
├── CR-20260815-001.md      # 当次变更
├── CR-20260822-002.md
└── README.md               # 索引
```

## 9. 度量与改进

每月一次变更 review：
- 变更数量
- 失败率
- MTTR（平均恢复时间）
- 回滚率
- 改进项 backlog

目标：
- L0/L1 变更失败率 < 5%
- L2/L3 变更失败率 < 2%
- 平均变更时长 < 30 分钟
- 回滚率 < 3%
