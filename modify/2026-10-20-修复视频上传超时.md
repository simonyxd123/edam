# 修复视频上传超时导致的上传中断

- **日期**：2026-10-20
- **触发来源**：`edamlog/error_20261019.txt`（13:08:36 / 13:10:18 / 13:10:58 三次同样的报错）
- **影响范围**：视频上传（`POST /api/v1/videos`）、文档上传（`POST /api/v1/documents`）同链路
- **关联方案书**：视频上传入库 + 秒传去重（file_hash）+ 异步转码触发

---

## 一、错误现象

```
org.springframework.web.multipart.MultipartException: Failed to parse multipart servlet request
  at ...StandardMultipartHttpServletRequest.handleParseFailure
  at ...DispatcherServlet.doPost
Caused by: IOFileUploadException: Processing of multipart/form-data request failed. java.io.EOFException
  at ...FileUploadBase.parseRequest
  at ...Streams.copy                      ← 服务端还在读请求体
Caused by: org.apache.catalina.connector.ClientAbortException: java.io.EOFException
  at ...InputBuffer.read
  at ...NioEndpoint$NioSocketWrapper.fillReadBuffer
Caused by: java.io.EOFException
```

## 二、根因

**不是服务端故障，是客户端主动断开了连接。**

关键证据在栈底：`Streams.copy` → `LimitedInputStream.read` 说明 Tomcat 在**仍在读取 multipart 请求体**时对端就没了，随后读到 EOF。

链路如下：

1. `web/src/api/client.ts:16` 共享 axios 实例设了 `timeout: 30000`；
2. `api.upload()` 没有覆盖它，于是**所有请求一律 30 秒超时**；
3. 前端允许 2GB（`Videos.vue:131`）、后端也允许 2GB（`application.yml:26-27`），但视频传不完 30 秒；
4. XHR 到点 abort → 断开 TCP → Tomcat multipart 解析器撞 EOF → 报上面的错；
5. 三次时间戳是用户反复重传同一文件。

### 顺带查出的三个连带问题

| # | 问题 | 位置 | 后果 |
|---|---|---|---|
| 2 | 拦截器把「无响应」当会话失效 | `client.ts:44-49` | 超时 → `status === undefined` → **清 token + 跳登录页**，上传失败还把用户踢下线 |
| 3 | 整文件进堆算 hash | `VideoService.java:107`、`DocumentService.java:67` | `digest.digest(file.getBytes())` 一次读 2GB 进 JVM 堆，OOM / GC 拖慢，反而更容易超时 |
| 4 | Nginx 上限 100M vs 后端 2GB | `dev/waf/nginx-modsecurity.conf:136`、helm `500m` | 生产环境 >100MB 直接 413（dev 走 Vite 代理不经 Nginx，故本次未触发） |

## 三、改动清单

### 1. `web/src/api/client.ts`

**a) 上传超时按文件大小动态放宽**

```ts
const DEFAULT_TIMEOUT_MS = 30000;
const UPLOAD_TIMEOUT_MIN_MS = 30 * 60 * 1000;       // 30 分钟
const UPLOAD_TIMEOUT_MAX_MS = 2 * 60 * 60 * 1000;   // 2 小时
const UPLOAD_ASSUMED_BYTES_PER_MS = (500 * 1024) / 1000; // 500 KB/s

function uploadTimeoutFor(sizeBytes?: number): number {
  if (!sizeBytes || sizeBytes <= 0) return UPLOAD_TIMEOUT_MAX_MS;
  const estimated = Math.ceil(sizeBytes / UPLOAD_ASSUMED_BYTES_PER_MS);
  return Math.min(UPLOAD_TIMEOUT_MAX_MS, Math.max(UPLOAD_TIMEOUT_MIN_MS, estimated));
}
```

`upload()` 从 FormData 取回原始 `File.size` 并透传 `timeout`。**`get/post/put/delete` 仍保持 30s**，不受影响。

**b) 拦截器不再把超时/取消判成会话失效**

```ts
const isTimeout  = error.code === 'ECONNABORTED' || error.code === 'ETIMEDOUT'
                || /timeout/i.test(error.message || '');
const isCanceled = axios.isCancel(error) || error.code === 'ERR_CANCELED';
```

分支顺序：`isTimeout`（提示「请求超时，请检查网络后重试」，**不清 token、不跳转**）→ `isCanceled`（用户主动取消，静默）→ 原有 `isSessionInvalid` 登出逻辑 → 423/429/5xx。

**c) 消除重复弹窗**

拦截器已 `ElMessage` 一次、View 的 `catch` 又弹一次。加 `(error as any).__handled = true` 标记，View 侧据此跳过。

### 2. `web/src/views/Videos.vue`、`web/src/views/Documents.vue`

`catch` 块改为 `if (!e?.__handled) ElMessage.error(...)`。

### 3. `backend/.../util/FileHashUtils.java`（新建）+ 两个 Service

流式计算 SHA-256，替代 `digest.digest(file.getBytes())`：

```java
byte[] buffer = new byte[8192];
try (InputStream in = file.getInputStream()) {
    int n;
    while ((n = in.read(buffer)) != -1) digest.update(buffer, 0, n);
}
```

哈希输出与旧实现**逐字节一致**（同样的小写 hex），秒传去重逻辑不受影响。纯内存/性能修复。

### 4. `dev/waf/nginx-modsecurity.conf`

- `client_max_body_size 100M` → `2g`
- `location /` 内补：`proxy_request_buffering off`（默认 on 会把 2GB 写盘再转后端）、`proxy_http_version 1.1`、`proxy_connect_timeout 60s`、`proxy_send_timeout 3600s`、`proxy_read_timeout 3600s`

### 5. `helm/edam/values.yaml`

- `clientMaxBodySize: "500m"` → `"2g"`
- ingress 注解：`proxy-body-size` → `"2g"`，`proxy-read-timeout` / `proxy-send-timeout` `"300"` → `"3600"`

### 6. `backend/.../exception/GlobalExceptionHandler.java`

新增两个 handler（`MultipartException` 比既有 `Exception.class` 更具体，Spring 优先匹配，不冲突）：

- `MaxUploadSizeExceededException` → **413**，`UPLOAD_413`
- `MultipartException` → 沿 cause 链判断客户端中断（`ClientAbortException` / `EOFException` / broken pipe）：
  - 中断 → `log.warn("client_aborted_upload")`，**不打整页堆栈**，400 `上传已中断，请重试`
  - 真解析失败 → `log.warn`，400 `上传内容解析失败，请重试`
