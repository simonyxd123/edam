### 阶段 3：容量基线计算（30 分钟）

#### 3.1 单 Pod QPS 上限

```bash
# 从 stress 档 JSON 中找拐点
python3 <<'EOF'
import json
data = json.load(open('results/stress-{TS}.json'))
m = data['metrics']
print(f"Peak RPS: {m['http_reqs']['values']['rate']:.1f}")
print(f"P99: {m['http_req_duration']['values']['p(99)']:.1f}ms")
print(f"Failed: {m['http_req_failed']['values']['rate']*100:.2f}%")
EOF
```

**单 Pod QPS 推荐公式**：

| 计算项 | 公式 | 来源 |
| --- | --- | --- |
| 单 Pod 容量上限 | stress 档实际达到的最大 RPS / 副本数 | stress 档实测 |
| 单 Pod 推荐（含缓冲）| 容量上限 × 0.8（20% 缓冲）| 工程经验 |

#### 3.2 推荐副本数（按用户量）

**每用户平均 QPS 假设**：

| 场景 | 每用户 QPS | 依据 |
| --- | --- | --- |
| 浏览为主 | 0.1-0.5 | 80% 时间在阅读，20% 操作 |
| 操作为主 | 1-5 | 管理员 / 重度用户 |
| 视频播放为主 | 0.5-2 | HLS 流式 |

**计算示例**：

```
1000 用户 × 0.5 QPS/用户 = 500 总 QPS
500 总 QPS / 200 QPS 单 Pod 推荐 = 2.5 → ⌈2.5⌉ = 3 副本
```

#### 3.3 HPA / 限流参数建议

从 peak 档实测推断：

| 参数 | 计算公式 | 依据 |
| --- | --- | --- |
| HPA CPU 阈值 | peak 档稳态 CPU 利用率 - 10% | 给扩容留余量 |
| HPA maxReplicas | 推荐副本数（5000 用户场景）× 1.5 | 给突发扩容留余量 |
| 每用户 QPS 限流 | 5-10 × 每用户平均 QPS | 防止滥用 |

#### 3.4 故障排查

| 症状 | 排查 |
| --- | --- |
| 单 Pod QPS 远低于期望 | 检查 stress 档拐点（是否 CPU/DB 提前打满）|
| 推荐副本数过高 | 重新评估"每用户平均 QPS"假设 |
| HPA 抖动 | 调整 stabilization window |

### 6.2 回滚

如本报告需回滚（仅修改文档）：

```bash
git revert <commit-hash>
```

如**发版决策**需回滚（v3.4 已部署）：

```bash
# ArgoCD 回滚
argocd app rollback edam-prod

# 或 kubectl
kubectl rollout undo deployment/edam-backend -n edam-prod
```

**回滚影响面**：仅发版流程，不影响任何业务数据。
