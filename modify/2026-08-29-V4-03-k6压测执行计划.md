## 五、执行步骤

### 5.1 阶段 0：环境准备（W1 前 1 天）

| 步骤 | 命令 | 备注 |
| --- | --- | --- |
| 安装 k6 | `brew install k6` 或 `apt install k6` | 本机或 CI Runner |
| 启动本地依赖 | `cd dev && docker compose up -d` | MySQL / Redis / MinIO / Vault / ES / RabbitMQ |
| 启动后端 | `cd backend && mvn spring-boot:run` | profile=local |
| 启动 Worker | `cd worker && pip install -r requirements.txt && python -m uvicorn edam_worker.main:app --reload --port 8001` | |
| Seed 测试用户 | `mysql -uroot -p edam < dev/db/seed/seed_k6_users.sql` | 100 个 TEST_001~TEST_NNN |
| 验证基础链路 | `curl http://localhost:8080/health/ready` | 应返回 200 |

### 5.2 阶段 1：烟囱测试（W1 D1）

```bash
cd perf/k6
k6 run --out json=results/smoke-$(date +%Y%m%d-%H%M%S).json scripts/smoke.js
./scripts/check-slo.sh smoke results/smoke-*.json | tail -1
```

**目标**：验证脚本无错 + 后端响应正常

**通过标准**：

- [ ] 脚本无语法错误，0.5 min 内开始跑
- [ ] 10 VUs × 5min 全程无错误日志
- [ ] check-slo.sh 输出"✓ 全达标"
- [ ] P99 < 800ms（放宽阈值）

### 5.3 阶段 2：负载测试（W1 D2-D3）

```bash
cd perf/k6
k6 run --out json=results/load-$(date +%Y%m%d-%H%M%S).json scripts/load-test.js
./scripts/check-slo.sh load results/load-*.json
```

**目标**：验证 SLO 达标

**通过标准**：

- [ ] **P50 ≤ 100ms**
- [ ] **P95 ≤ 200ms**
- [ ] **P99 ≤ 500ms**
- [ ] **失败率 ≤ 1%**
- [ ] 200 QPS 稳态无降级

### 5.4 阶段 3：峰值测试（W1 D4）

```bash
cd perf/k6
k6 run --out json=results/peak-$(date +%Y%m%d-%H%M%S).json scripts/peak-test.js
./scripts/check-slo.sh peak results/peak-*.json
```

**目标**：验证弹性 + 告警

**通过标准**：

- [ ] P50 ≤ 150ms（放宽）
- [ ] P95 ≤ 300ms（放宽）
- [ ] P99 ≤ 800ms（放宽）
- [ ] HPA 触发（监控 `kube_horizontalpodautoscaler_status_current_replicas`）
- [ ] 告警正常（无 P1 告警）

### 5.5 阶段 4：极限测试（W1 D5）

```bash
cd perf/k6
k6 run --out json=results/stress-$(date +%Y%m%d-%H%M%S).json scripts/stress-test.js
```

**目标**：找瓶颈（不设阈值）

**输出**：

- 首个错误率 > 5% 的 QPS 阈值
- 首个 P99 > 1s 的端点
- 资源使用率打满的组件（CPU / 内存 / DB 连接数 / Redis QPS）

## 七、风险与回滚

### 7.1 执行风险

| 风险 | 严重度 | 缓解 |
| --- | --- | --- |
| **R-1**：极限档把生产数据库打挂 | 高 | 在 staging 环境跑极限档，本地 dev 不跑极限档 |
| **R-2**：测试用户池污染业务数据 | 中 | 用户名前缀 `TEST_` + 单独角色 + CI 自动清理 |
| **R-3**：k6 进程 OOM | 低 | 使用 docker run 加 `--memory=2g` |
| **R-4**：压测影响其他测试 | 低 | 在 staging 维护窗口跑 + Slack 提前通知 |

### 7.2 结果风险

| 风险 | 严重度 | 缓解 |
| --- | --- | --- |
| **R-5**：SLO 不达标 | 中 | 找到瓶颈 → V4-04（短期后续）或列入 v3.5 路线图 |
| **R-6**：报告 HTML 乱码 | 低 | UTF-8 强制 + 浏览器切换编码 |
| **R-7**：CI 集成失败 | 低 | 本地手动跑通 + check-slo.sh 单测 |

### 7.3 回滚方案

若本次推进需回滚（仅 k6 套件本身，不影响业务代码）：

```bash
cd G:/data/project/edam
```
