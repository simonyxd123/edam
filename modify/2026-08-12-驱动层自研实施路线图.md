## 二、Windows minifilter POC 任务书

### 2.1 技术选型

| 维度 | 选型 | 理由 |
| --- | --- | --- |
| 驱动框架 | **WDF (Windows Driver Framework)** | Microsoft 推荐，比传统 WDM 易维护 |
| minifilter 类型 | **File System Mini Filter** | Windows Vista+ 标准方案 |
| 加密算法 | **AES-256-GCM + SM4-GCM（双轨）** | 国际 + 国密双轨兼容 |
| 密钥管理 | **HashiCorp Vault Transit** | 与后端 Vault 集群统一 |
| 驱动签名 | **EV 代码签名 + Microsoft 硬件认证** | 强制要求，避免 SmartScreen 拦截 |
| 调试工具 | WinDbg + Driver Verifier + KDNET | 标准内核调试套件 |
| 测试工具 | HLK（Hardware Lab Kit） | Microsoft 官方认证测试 |

### 2.2 POC 范围（4 周）

**目标**：验证单文件加解密闭环可用

**功能清单**：
- ✅ 注册 minifilter（IRegistryPath、Altitude 数字签名）
- ✅ 拦截 IRP_MJ_CREATE / IRP_MJ_WRITE / IRP_MJ_READ
- ✅ 单文件 AES-256-GCM 加解密（key 从 Vault 获取）
- ✅ 加密文件头标识（magic bytes：`EDAM\x01\x00`）
- ✅ 写时加密 + 读时解密透明
- ✅ 进程白名单（绕过特定进程如备份工具）
- ❌ 目录级策略（Phase 2）
- ❌ 跨平台（macOS/Linux，Phase 3-4）

### 2.3 关键代码骨架

```c
// edam_minifilter.c - 核心骨架
#include <fltKernel.h>
#include <dontuse.h>
#include <suppress.h>

#define EDAM_ALTITUDE 370000  // 高于主流杀毒（避免冲突）
#define EDAM_HEADER_MAGIC "EDAM\x01\x00"

PFLT_FILTER gFilterHandle;
ULONG gTraceFlags;

// 注册 minifilter
NTSTATUS DriverEntry(PDRIVER_OBJECT DriverObject, PUNICODE_STRING RegistryPath) {
    FLT_REGISTRATION filter_reg = {
        sizeof(FLT_REGISTRATION),
        FLT_REGISTRATION_VERSION,
        0,
        NULL,
        FLT_CONTEXT_REGISTRATION,  // 上下文管理
        EdamCallbacks,             // 回调表
        EdamUnload,
        EdamInstanceSetup,
        EdamInstanceQueryTeardown,
        EDAM_ALTITUDE,             // 加载顺序
        NULL
    };
    return FltRegisterFilter(DriverObject, &filter_reg, &gFilterHandle);
}

// 关键回调：写前加密
FLT_PREOP_CALLBACK_STATUS EdamPreWrite(
    PFLT_CALLBACK_DATA Data,
    PCFLT_RELATED_OBJECTS FltObjects,
    PVOID *CompletionContext) {

    // 1. 跳过内核调用 & 白名单进程
    if (IsKernelCall(Data) || IsWhitelistedProcess(Data)) {
        return FLT_PREOP_SUCCESS_NO_CALLBACK;
    }

    // 2. 检查文件扩展名（仅加密 .docx/.pdf/.xlsx 等）
    if (!IsTargetExtension(FltObjects->FileObject)) {
        return FLT_PREOP_SUCCESS_NO_CALLBACK;
    }

    // 3. 加密前检查是否已加密
    PFLT_CONTEXT ctx;
    if (FltGetFileContext(FltObjects->Instance, FltObjects->FileObject, &ctx) == STATUS_SUCCESS) {
        return FLT_PREOP_SUCCESS_NO_CALLBACK;
    }

    // 4. 加密缓冲区
    PUCHAR buffer = ...; // 获取写入缓冲区
    ULONG length = Data->Iopb->Parameters.Write.Length;
    EncryptBufferInPlace(buffer, length, GetFileKey(FltObjects));

    return FLT_PREOP_SUCCESS_NO_CALLBACK;
}
```

## 三、跨平台策略

### 3.1 平台矩阵

| 平台 | 用户占比 | 实施框架 | 优先级 | 工期 |
| --- | --- | --- | --- | --- |
| **Windows** | 70% | minifilter (WDF) | **P0（Phase 2）** | 4-6 月 |
| **macOS** | 15% | Endpoint Security Framework | P1（Phase 3） | 3-4 月 |
| **Linux** | 10% | FUSE + gocryptfs 参考 | P1（Phase 3） | 3-4 月 |
| **iOS/Android** | 5% | MDM + 应用沙箱 | P2（Phase 4） | 1-2 月 |

### 3.2 macOS Endpoint Security Framework（ESF）

**关键 API**：
- `es_new_client()` - 注册 ESF 客户端
- `es_subscribe_file_events()` - 监听文件系统事件
- `es_unregister_file_path()` - 路径级加密策略

**实施要点**：
- macOS 10.15+ 必须使用 System Extension（取代老版 KEXT）
- 必须经 Apple Notarization 公证
- 内核事件 + 用户态策略双层架构

### 3.3 Linux FUSE

**关键库**：`libfuse3` + `gocryptfs` 参考实现

**实施要点**：
- 用户态文件系统（无需内核模块）
- 性能：FUSE 中等开销，可接受
- 兼容性：kernel 4.18+ 现代特性；如需内核态用 `passthrough` 选项
- 加密：复用 AES-256-GCM 算法（与 Windows 一致）

### 3.4 移动端（iOS/Android）

**移动端不部署文件级透明加密**，采用应用沙箱方案：

| 平台 | 方案 |
| --- | --- |
| iOS | MDM + iOS 17+ Managed App Configuration + Encrypted Notes API |
| Android | Android Enterprise + 工作资料隔离 + App Sandbox |

**统一策略**：
- 移动端访问内部视频/文档强制走 HLS + Canvas 水印
- 录屏检测 + 强制 HTTPS + 设备指纹绑定

### 4.1 高风险（D-1、D-5、D-6、D-8）应对

**D-1 BSOD 应对流程**：
1. 启用 Driver Verifier（`verifier.exe /standard /all`）
2. 灰度发布：内部员工 10 人 → 50 人 → 200 人 → 全体
4. 每阶段观察 7 天，BSOD 率 > 0.01% 立即回滚
5. 自动 dump 上报（OneDriver DUMP_COLLECT）

**D-5 驱动被禁用应对**：
- 终端每 5 分钟心跳上报驱动状态
- 服务端检测离线超 24h → 自动吊销该用户文件密钥
- 文档外发网关强制检查（5.1.4 节）

**D-6 应急解密工具**：
- 准备 WinPE 启动盘 + 离线解密工具
- 用户忘记密码或驱动故障时，从 Vault 拉密钥解密
- 工具需 EV 签名 + 受控发布（防滥用）

**D-8 超预算应对**：
- 每月预算评审（计划 vs 实际）
- 超 50% 触发 Plan B 评估会
- 已与天喻/IP-guard 预留 PoC 通道（2 周可启动）
