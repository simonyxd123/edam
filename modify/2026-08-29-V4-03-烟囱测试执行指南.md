### 阶段 3：加载 k6 测试用户 seed（预计 2 分钟）

#### 3.1 验证 seed 是否已自动加载

MySQL 容器首次启动时会自动执行 `dev/db/seed/` 下所有 SQL（按文件名顺序）。但**已初始化的容器不会重新执行**。

```bash
docker exec edam-mysql mysql -uroot -prootpass edam -e "
SELECT * FROM v_k6_seed_status\G
"
```

**期望输出**：

```
             role_exists: 1
              role_perms: 7
                k6_users: 100
      k6_role_assigned: 100
```

#### 3.2 如未加载（首次或修复）

**方式 A：手动执行 seed**

```bash
docker exec -i edam-mysql mysql -uroot -prootpass edam < \
  dev/db/seed/V20260829_2000__seed_k6_users.sql
```

**方式 B：删除 MySQL 数据卷后重启（注意：会清空所有数据）**

```bash
docker compose down -v
docker compose up -d
```

#### 3.3 验证

```bash
# 1. 检查 k6_tester 角色
docker exec edam-mysql mysql -uroot -prootpass edam -e "
SELECT id, code, name FROM sys_role WHERE id = 5;
"
# 期望: 5 | k6_tester | k6 压测专用

# 2. 检查权限
docker exec edam-mysql mysql -uroot -prootpass edam -e "
SELECT p.code FROM sys_role_permission rp
JOIN sys_permission p ON rp.permission_id = p.id
WHERE rp.role_id = 5 ORDER BY p.code;
"
# 期望: 7 行权限

# 3. 检查用户数量
docker exec edam-mysql mysql -uroot -prootpass edam -e "
SELECT COUNT(*) AS cnt FROM sys_user WHERE employee_no LIKE 'TEST_%';
"
# 期望: cnt = 100

# 4. 登录验证（用 curl 测一个用户）
curl -s -X POST http://localhost:8080/api/v1/auth/login \
  -H "Content-Type: application/json" \
  -d '{"employeeNo":"TEST_001","password":"TestP@ssw0rd!"}' | head -c 200
# 期望: 包含 "access_token"
```

#### 故障排查

| 症状 | 排查 |
| --- | --- |
| `v_k6_seed_status` 不存在 | seed 未加载，重跑 3.2 步骤 |
| 用户数 < 100 | `docker logs edam-mysql | grep V20260829` 查看是否报错 |
| 登录返回 401 | 检查后端 BCrypt 配置（应支持 `$2a$` / `$2b$` 前缀）|

## 六、风险与回滚

### 6.1 风险

| 风险 | 严重度 | 缓解 |
| --- | --- | --- |
| **R-1**：dev 环境的 MySQL/Redis 被污染 | 低 | dev 环境隔离，无真实数据 |
