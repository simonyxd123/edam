### 阶段 5：定时任务启用（5 分钟）

#### 5.1 验证 cron 表达式

perf.yml 中已配置：

```yaml
schedule:
  - cron: '0 2 * * 1'  # 每周一凌晨 2 点（UTC）
```

**等价于**：北京时间每周一上午 10:00

#### 5.2 验证定时触发

GitHub Actions 不会立即触发定时任务。验证方法：

```bash
# 1. Settings → Actions → General → Workflow permissions
#    确认 "Read and write permissions" 已勾选
# 2. Actions → Performance Test (k6) → 右上角 "..." → View workflow file
#    确认 schedule 配置正确
```

#### 5.3 时区注意

GitHub Actions cron 使用 **UTC 时区**：

| 北京时间 | UTC 时间 | cron 表达式 |
| --- | --- | --- |
| 每周一 09:00 | 每周一 01:00 | `0 1 * * 1` |
| 每周一 10:00 | 每周一 02:00 | `0 2 * * 1`（本配置）|
| 每周一 14:00 | 每周一 06:00 | `0 6 * * 1` |

#### 5.4 故障排查

| 症状 | 排查 |
| --- | --- |
| 定时任务未触发 | GitHub Actions 定时有 5-10min 延迟 + 高峰期可能延迟 30min |
| 时区不对 | 确认使用 UTC 时区 |

## 七、风险与回滚

### 7.1 风险

| 风险 | 严重度 | 缓解 |
| --- | --- | --- |
| **R-1**：CI 配置错误导致每次跑失败 | 中 | 阶段 4 失败调试前不启用定时 |
| **R-2**：Slack webhook 泄露 | 高 | webhook URL 仅作 Secret 存储 + 定期 rotate |
| **R-3**：CI 资源消耗（4 jobs × 20min）| 中 | 限速（concurrency）+ 仅周一跑 |
| **R-4**：定时任务触发时 staging 不可用 | 中 | workflow 失败时 Slack 通知 + 不影响生产 |

### 7.2 回滚

如 workflow 需禁用：

```bash
# 方式 1：临时禁用
# GitHub → Actions → Performance Test (k6) → ... → Disable workflow

# 方式 2：删除文件
git rm .github/workflows/perf.yml
git commit -m "ci: 禁用 k6 压测 workflow（紧急回滚）"
git push

# 方式 3：回滚到上一版本
git revert <perf-yml-commit>
```

**回滚影响面**：仅 CI 配置，不影响任何运行时。
