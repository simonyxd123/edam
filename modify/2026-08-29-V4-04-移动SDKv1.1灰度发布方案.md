## 三、6 阶段执行步骤

### 阶段 1：灰度策略配置（W3 D1-D2，2 天）

#### 1.1 灰度比例设计

| 阶段 | 比例 | 持续时间 | 监控时长 | 通过标准 |
| --- | --- | --- | --- | --- |
| **预热**（白名单）| 0%（手选 50 用户）| 2 天 | 48h | 崩溃率 = 0% |
| **Stage 1** | **10%**（自动 + 白名单）| 3 天 | 72h | 崩溃率 < 0.5% |
| **Stage 2** | **50%**（自动 + 白名单）| 3 天 | 72h | 崩溃率 < 0.3% |
| **Stage 3** | **100%**（全量）| 持续 | — | 崩溃率 < 0.2% |

**总灰度周期**：~8-10 天

#### 1.2 白名单 + 黑名单策略

**白名单**（50 用户，立即启用）：

- 公司内部员工（`@example.com` 域名）
- 测试团队成员（10 人）
- 重点客户（5 个，已签 NDA）
- 应急联络人（5 个）

**黑名单**（强制回退到 v1.0）：

- 已报告严重 bug 的用户
- 系统版本不兼容的用户（iOS < 14 / Android < 8）

#### 1.3 灰度配置 SDK 集成

新增 2 个文件（已就绪）：

- `mobile-sdk/ios/EDAMPlayer/GrayReleaseConfig.swift`（iOS Swift 单例）
- `mobile-sdk/android/edam-player/src/main/java/com/example/edam/player/GrayReleaseConfig.kt`（Android Kotlin 单例）

#### 1.4 故障排查

| 症状 | 排查 |
| --- | --- |
| 灰度比例不生效 | 检查 SDK 初始化是否在 Application.onCreate |
| 白名单不生效 | 检查 SharedPreferences 持久化 + Key/Value 拼写 |
| 哈希分流不稳定 | 检查 stableHash 函数是否使用稳定的算法（SHA-256）|

### 阶段 2：监控集成（W3 D3-D5，3 天）

#### 2.1 监控指标设计

| 类别 | 指标 | 阈值（warning）| 阈值（critical）|
| --- | --- | --- | --- |
| **稳定性** | 崩溃率（v1.1）| > 0.3% | > 0.5% |
| | ANR 率（Android）| > 0.1% | > 0.3% |
| | Crash free 用户 | < 99.7% | < 99.5% |
| **性能** | SDK 启动时间 | > 200ms | > 500ms |
| | 内存增量（v1.1 vs v1.0）| > 30MB | > 50MB |
| | 首帧延迟（视频播放）| > 300ms | > 500ms |
| **用户体验** | 文档预览成功率 | < 98% | < 95% |
| | 离线缓存命中率 | < 70% | < 50% |
| | 录屏检测准确率 | < 95% | < 90% |

#### 2.2 监控 SDK 集成

```swift
// iOS - 集成到 EDAMPlayer 初始化
import EDAMAnalytics  // 公司自研埋点 SDK

EDAMAnalytics.track(event: "gray_release_status", properties: [
    "userId": currentUserId,
    "feature": "document_preview",
    "enabled": GrayReleaseConfig.shared.isFeatureEnabled(userId: currentUserId, feature: "document_preview"),
    "sdkVersion": "1.1.0",
])
```

```kotlin
// Android - 集成到 EDAMPlayer 初始化
EDAMAnalytics.track("gray_release_status", mapOf(
    "userId" to currentUserId,
    "feature" to "document_preview",
    "enabled" to GrayReleaseConfig.isFeatureEnabled(currentUserId, "document_preview"),
    "sdkVersion" to "1.1.0",
))
```

#### 2.3 监控看板

- URL：`https://grafana.example.com/d/edam-mobile-gray`
- 面板：崩溃率 / 启动时间 / 内存 / 文档预览成功率
- 实时刷新：1 分钟
- 告警：触发阈值自动推送到 Slack #mobile-alerts

#### 2.4 故障排查

| 症状 | 排查 |
| --- | --- |
| 埋点数据缺失 | 检查埋点 SDK 集成 + 网络 |
| 监控看板无数据 | 检查 Prometheus 抓取 + PromQL |
| 告警风暴 | 检查告警规则 + inhibit_rules |

### 阶段 3：灰度 SOP（W3 D6-D7，2 天）

#### 3.1 灰度推进决策矩阵

| Stage | 推进条件 | 回退条件 | 暂停条件 |
| --- | --- | --- | --- |
| **Stage 1 → 2** | 崩溃率 < 0.5% + 监控时长 ≥ 72h | 崩溃率 > 1% | 监控时长不足 48h |
| **Stage 2 → 3** | 崩溃率 < 0.3% + 监控时长 ≥ 72h | 崩溃率 > 0.5% | 监控时长不足 48h |
| **Stage 3（全量）** | 持续监控 2 周 | 崩溃率 > 0.2% | — |

#### 3.2 灰度推进命令

```bash
# Stage 1 → 10%
curl -X POST https://admin.example.com/api/gray-release \
  -H "Authorization: Bearer $ADMIN_TOKEN" \
  -H "Content-Type: application/json" \
  -d '{
    "feature": "mobile_sdk_v1_1",
    "stage": "stage1",
    "percentage": 10,
    "platforms": ["ios", "android"],
    "release_notes": "新增文档预览 + 离线缓存 + 录屏检测"
  }'

# Stage 2 → 50%
curl -X POST ... -d '{ "stage": "stage2", "percentage": 50, ... }'

# Stage 3 → 100%
curl -X POST ... -d '{ "stage": "stage3", "percentage": 100, ... }'

# 紧急回滚
curl -X POST ... -d '{ "stage": "rollback", "percentage": 0, ... }'
```

#### 3.3 灰度推进会议

- **频率**：每个 Stage 结束后召开（3 次）
- **时长**：30 分钟
- **参会人**：移动端 TL + SRE + QA + 产品经理
- **议程**：监控数据回顾 + 决策（推进/暂停/回退）

#### 3.4 故障排查

| 症状 | 排查 |
| --- | --- |
| API 调用失败 | 检查 admin API 权限 + token |
| 比例不生效 | 检查后端灰度服务 + SDK 配置同步 |

### 阶段 4：回滚预案（W4 D1-D2，2 天）

#### 4.1 回滚触发条件

| 严重度 | 触发条件 | 回滚方式 |
| --- | --- | --- |
| **P0** | 崩溃率 > 1% | **立即全量回退**（30min） |
| **P0** | 严重数据丢失 | 立即回退 |
| **P1** | 崩溃率 > 0.5% 持续 1h | 当日全量回退 |
| **P1** | 核心功能不可用 | 当日回退 |
| **P2** | 性能退化 > 30% | 下个 Stage 推迟 |
| **P2** | 用户反馈量增加 | 评估后决定 |

#### 4.2 回滚步骤

```bash
# 1. 立即禁用灰度
curl -X POST https://admin.example.com/api/gray-release \
  -d '{ "feature": "mobile_sdk_v1_1", "stage": "rollback", "percentage": 0, ... }'

# 2. 等待 SDK 配置同步（最长 5min）
# 后端配置变更 → SDK 拉取新配置 → 客户端生效

# 3. 验证回退
# - 监控看板：崩溃率恢复到 v1.0 水平
# - 用户反馈：恢复正常

# 4. 通知团队
# Slack #mobile-alerts: "v1.1 已回退到 v1.0，原因：xxx"

# 5. 写复盘报告
# modify/2026-09-XX-V4-04-灰度回退复盘.md
```

#### 4.3 故障排查

| 症状 | 排查 |
| --- | --- |
| 回退不生效 | 检查 SDK 配置拉取 + SharedPreferences 同步 |
| 客户端不更新 | 强制升级（forceUpdate=true）|
